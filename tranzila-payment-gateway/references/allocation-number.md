# ITA allocation number (mispar haktza'a): statute detail

Companion to Step 10 of SKILL.md. The band schedule (keyed to the invoice's own date) is in SKILL.md; this file holds the two statutory limits, quoted verbatim, that any validation built on it must respect.

Two limits worth wiring into any validation you build on this, both quoted from the statute. Zero-rated and exempt-only invoices are outside the requirement, because s.47(א2)(1) applies only `לעניין חשבונית מס שהוצאה בשל עסקה שהמס שחל לגביה אינו בשיעור אפס`, so an export invoice needs no number however large. And the effect of a missing number is precise: s.38(א1) disallows the BUYER's input-VAT deduction, `לא יותר ניכוי מס התשומות הכלול בחשבונית מס שסכומה, בלא המס, עולה על 5,000 שקלים חדשים (מינואר 2026 ועד מאי 2026: 10,000 שקלים חדשים) ושאינה כוללת מספר שהקצה לה המנהל`. It does not make the invoice void, so do not describe it that way. Note two things in that text: it says `עולה על` (EXCEEDS), so an invoice exactly at a band figure is outside the rule, and it carries the January-to-May 2026 row itself, so the schedule is confirmable from the statute rather than only from vendor summaries. There is also no buyer-request condition there: the demand in s.47(א2)(1) governs whether the SELLER breached a duty, not whether the buyer can deduct, so never treat "nobody asked" as a pass when validating.
